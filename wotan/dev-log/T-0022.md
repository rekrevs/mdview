## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh).

- Vendor `mermaid@12.2.0` `dist/mermaid.min.js` (IIFE, 5.49 MB, no dynamic import/eval/CDN). ESM build rejected (lazy chunks). Requires Safari 17.4+/ES2024; failure falls back to source.
- Lazy-inject the script once only when a document has a mermaid figure; detect load failure (global missing) → error state. No CSP/Swift changes.
- `initialize({startOnLoad:false, securityLevel:'strict', suppressErrorRendering:true, theme, layout:'dagre', fontFamily, secure:[…defaults,'themeCSS']})`.
- Fence → `figure.mermaid[data-mermaid=NONCE][data-state=pending]` with copy button, svg slot, hidden error figcaption and escaped source `pre`. Per-page nonce so author HTML can't forge.
- `hydrateDiagrams(gen)` after innerHTML: cache (theme+source+occurrence, ~64) inserted synchronously; misses queued viewport-first, one per macrotask, abort on generation change; scroll compensation for figures above viewport; SVG sized in rem for zoom; `mdview.diagramsSettled()` test hook; `options.diagrams===false` for Quick Look.
- Theme via matchMedia, re-render on change. Errors: textContent caption + visible source; >50 000 chars explicit error.
- Copy: snap to `[data-mermaid]`, replace with fenced ```mermaid source; copy button posts raw source. Find excludes diagrams.
- Licensing: manifest `bundled` list + `licenses/mermaid-bundled.txt` (elkjs EPL-2.0, DOMPurify MPL/Apache, chevrotain Apache, d3 ISC, …); validate-bundle size/marker check; README/CLAUDE.md/THIRD_PARTY.
- Tests: jsdom with stubbed mermaid for structure/loader/error/cache/theme/copy/find/limits + smoke parse; GUI with real SVG bbox, strict-mode attack fixture, theme switch, zoom, copy, find, scroll stability, 40-diagram timing.

## Implementation Notes

- Vendored `mermaid@12.2.0` `dist/mermaid.min.js` (5 494 801 bytes; npm sha512 matches the registry `w7nr/SFrLO7…`; manifest sha256 `071914164d0f…`). The bundle is a single esbuild IIFE that sets `globalThis.mermaid`. I checked it: no `import(`, no `eval(`, no `XMLHttpRequest`/`importScripts`/CDN hosts and no source map. `fetch(` hits are KaTeX's token gullet. The one `new Worker` is elkjs's optional `workerUrl` factory, which we never use. The three `Function("return this")` hits are lodash's global fallback; they are not reached in a browser because `self` exists, and CSP would block them anyway. The remote URLs in the bundle are documentation links and XML namespaces only.
- `scripts/vendor-renderer.py`: added Mermaid to `PACKAGES`, retries on download (the earlier IncompleteRead problem), and a `bundled` array plus `licenses/mermaid-bundled.txt` for the Mermaid entry. Both are generated from the new data file `scripts/mermaid-bundled.json` (108 packages: name, version, license, lockfile sha512). Archives come from `<dir>/bundled/` in local mode or are downloaded otherwise, and the script verifies each one against the recorded integrity. Output is deterministic: two runs gave identical sha1 for the manifest and the notices file. All pre-existing vendored files are byte-identical (`git diff --stat` shows only manifest additions).
- How the bundled list was determined: the bundle's own license banner names only DOMPurify 3.4.12, lodash-es 4.18.1 and the inner notices of cytoscape. I computed the runtime closure of `packages/mermaid` and `packages/parser` from Mermaid's `pnpm-lock.yaml` at tag `mermaid@12.2.0` (an `npm install --before` reconstruction gave wrong versions, e.g. DOMPurify 3.4.17). esbuild module paths left in the bundle (`vscode-jsonrpc`, `vscode-languageserver-protocol/-types`) show that langium's runtime is bundled although langium is only a devDependency of the parser, so I added `langium@4.4.0` as a root. I excluded type-only `@types/*`. The result is an upper bound: Node-only branches such as Iconify's filesystem loader and d3-dsv's CLI dependencies are probably tree-shaken out, but I list them rather than guess. Licenses: 60 MIT, 33 ISC, 6 BSD-3-Clause, 6 Apache-2.0 (chevrotain), DOMPurify MPL-2.0 OR Apache-2.0, elkjs EPL-2.0, robust-predicates Unlicense. The notices file (≈159 KB) contains every license file from each npm archive. Exact duplicate texts are referenced back to their first occurrence. It opens with an explicit source-code notice for elkjs (EPL-2.0 object-code distribution) and DOMPurify.
- `renderer.js`:
  - Fence `mermaid` (case-insensitive info string) produces `figure.mermaid[data-mermaid=NONCE][data-state=pending]` with the Copy button, an svg slot, a hidden error figcaption and the escaped `pre.mermaid-source > code`. NONCE is 24 hex characters from `crypto.getRandomValues`, one per page. `env.diagrams === false` (`render(md, {diagrams:false})`) keeps a plain `code.language-mermaid` block, and the unchanged-render shortcut takes that option into account.
  - `hydrateDiagrams()` runs in `render()` after insertion and before the scroll restore, and again on every `prefers-color-scheme` change (listener registered on the first diagram). Each call bumps the generation.
  - Cache: keyed by theme + occurrence + source, LRU of 64 entries, holding errors as well as SVGs. Hits are applied synchronously.
  - Misses go to a queue. The script is injected lazily, exactly once. After load the code checks that `mermaid.render` and `mermaid.initialize` are functions; otherwise every pending figure goes to the error state.
  - Each queue step picks the best-ranked remaining figure at that moment (visible, then below, then above the viewport), so ranking happens after the scroll restore and follows the reader's scrolling. One `mermaid.render` runs per macrotask (`setTimeout 0`), and a step stops when the generation has changed. Stale results are cached but not applied.
  - `initialize` + `render` pairs are serialized on one promise chain, so a theme switch can never mix configurations. Ids are `mdview-mermaid-${nonce}-${gen}-${i}`; the nonce stops Mermaid's removal of existing `#id` elements from hitting an author heading. Leftover `#id`, `#d<id>` and `#i<id>` elements outside `main` are removed after every render.
  - SVG: `width`/`height` attributes are removed and `style.width = viewBox width/16 rem`, `max-width:100%`, `height:auto`.
  - Error caption: `textContent` "Diagram could not be rendered: <message>". Sources over 50 000 characters fail explicitly without loading Mermaid.
  - `mdview.diagramsSettled()` returns a promise that resolves when the current generation has finished.
  - Config: `startOnLoad:false, securityLevel:'strict', suppressErrorRendering:true, theme:'default'|'dark', layout:'dagre', fontFamily` (reader font), `secure:` Mermaid's default secure keys plus `themeCSS`. The option names were checked in the 12.2.0 bundle. Mermaid 12 defaults to `layout:"elk"`, so the explicit `'dagre'` matters.
  - Copy: selection boundaries snap to `figure[data-mermaid]` (then `[data-math]`). Each nonce figure in the copied fragment becomes `<pre><code>` with a fenced block whose fence is longer than any backtick run in the source. The Copy-button handler now reads `:scope > pre > code`.
  - Find: `[data-mermaid]` is added to the skip selector.
- `reader.css`: centred figure with overflow-x; the empty slot is hidden; pending source is muted; rendered source is hidden; error caption is red pre-wrap and the error source has a red border; the Copy button appears on figure hover; print uses break-inside:avoid.
- CSP unchanged: `script-src 'self'` covers `vendor/`, and `style-src 'unsafe-inline'` covers Mermaid's inline styles and `<style>`. No Swift changes.
- `validate-bundle.sh`: requires `mermaid.min.js`, `licenses/mermaid.txt` and `licenses/mermaid-bundled.txt`; checks size ≥ 1 MB plus the markers `globalThis["mermaid"]` and `"12.2.0"`; checks that the notices contain the EPL text. Negative control: a copy with a truncated 2 MB bundle fails with "incomplete Mermaid build".
- Docs: README (feature, copy/find, strict mode, dagre, no icon packs, Safari 17.4+, ~5.5 MB; removed "Mermaid … not implemented"), CLAUDE.md (library and loading/licensing note), THIRD_PARTY.md (Mermaid row plus a table of bundled non-MIT components).

## Obstacles

- `mermaid.min.js` cannot run under jsdom's strict-mode `eval`, because its top-level `var` becomes local. The smoke test injects it as a classic `<script>` with `runScripts:'dangerously'`. jsdom has no `getBBox`, so the smoke test covers parse only; rendering is covered in the GUI.
- Mermaid itself defines `globalThis.injected ??= {includeLargeFeatures…}`, a build feature-flag object. That broke the planned `window.injected` canary and the existing final check (`<script>window.injected=true</script>`). I renamed the canaries to `window.__mermaidPwned` and `window.__documentScript`; this was diagnosed via an own-property check, not a real injection.
- WebKit records no resource-timing entries for `file:` loads, so the positive "Mermaid came from the bundle" check uses the resolved script URL (`file:…/.app/Contents/Resources/…`). The negative "no non-file resources" check stays.
- Reading-position compensation: WebKit performs native scroll anchoring synchronously (probe: prepending 500 px moved scrollY from 2664 to 3164 immediately), so the planned `scrollBy(height delta)` doubled the correction (anchor drift 902 px). Correcting by the figure's actual bottom shift still drifted 11 px over 27 figures, because anchoring corrects in whole pixels (≈0.4 px residual each). Final approach: correct only the remaining shift and carry the sub-pixel remainder across the pass. Drift is now ≤0.6 px.
- Ranking queued figures inside `render()` happened before the scroll restore (the unit test exposed this), so ranking now happens at each step.

## Outcome

Independent verification by the coordinating session: `make check` Swift 12/12 + renderer 64/64, `make gui-test` 86/86 (re-run after increasing figure margin to `1.5rem 0`, since adjacent diagrams looked cramped in the dark snapshot), `make validate-bundle` OK, app 8.3 MB.


Mermaid fences render offline as strict-mode SVG diagrams that follow the light/dark theme and zoom, and they fall back visibly to source plus an error. They copy as fenced source, stay out of find, and survive reloads through a synchronous cache. Mermaid is loaded only for documents that contain diagrams.

Residual risks:
1. The Safari 17.4/ES2024 requirement comes from the plan and was not tested on older WebKit; the failure path (error state with source) is unit-tested.
2. The bundled-component list is an upper bound derived from the lockfile, not from an esbuild metafile.
3. Mermaid strict mode still allows author-controlled styling of a diagram via `classDef`/`style`, scoped to that SVG; `themeCSS` is secured.
4. With htmlLabels, Mermaid inserts DOMPurify-sanitized HTML in `foreignObject`; inline handlers are additionally blocked by CSP (proved by the existing CSP probe).
5. A theme switch re-renders every uncached diagram, one per macrotask.

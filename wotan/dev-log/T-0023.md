# T-0023: Show YAML front matter as metadata

**Status**: DONE | **Size**: M
**Phase**: -

## Context

GitHub renders a leading `---` YAML block as a table; mdview currently renders it as Markdown (rule + text).

## Acceptance Criteria

- [x] A leading front-matter block is detected and shown as a compact metadata table or collapsible block
- [x] Non-leading `---` and documents without front matter are unchanged
- [x] Malformed front matter falls back to visible source
- [x] Renderer tests and GUI evidence; README updated

## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh). Option (b): strict in-house subset parser with highlighted-source fallback; no new dependency.

- `strip_bom` core rule after `normalize` (BOM currently leaks into an `<h2>`).
- `front_matter` block rule before `table`: only at line 0 of root with `bMarks[0]===0`; opener `---`/`+++`, closer `---`/`...`/`+++`; keeps markdown-it line maps. Today a leading block becomes `<hr><h2>title: x</h2>` and leaks into the outline.
- `parseFrontMatter` → ordered `[key, value]` pairs for column-0 scalars, simple quoted keys/values, flow scalar lists, block `- item` lists; returns null for nested maps, block scalars, anchors/aliases/tags, flow maps, multi-line scalars, duplicates, tabs, top-level lists.
- Renderer: empty → nothing; TOML or null → `.front-matter-source` highlighted code (exact source); else GitHub-style `table.front-matter` (keys header row, values row, list → nested table), all escaped, no inline Markdown.
- CSS: compact table, muted "Front matter" label via `::before` on the source fallback.
- Deviation from GitHub: `+++` TOML shown as highlighted source rather than text. Nested YAML shows source instead of nested tables (js-yaml is the upgrade path).
- Tests: ten renderer cases (table structure, BOM/CRLF, non-matching inputs, empty/only-front-matter, fallbacks, inertness, TOML, find/copy, math after, tricky values) + GUI check (first child, no hr, Swift outline, native copy, narrow width).

## Log

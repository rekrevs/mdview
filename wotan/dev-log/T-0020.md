# T-0020: Render GitHub alerts and footnotes

**Status**: READY | **Size**: M
**Phase**: -

## Context

GitHub renders `> [!NOTE|TIP|IMPORTANT|WARNING|CAUTION]` alerts and `[^n]` footnotes; mdview shows them as plain quotes/text. Part of the best-in-class parity work (2026-11-03 comparison with SharePoint/OneDrive and GitHub).

## Acceptance Criteria

- [ ] All five GitHub alert types render with title, icon and colour in light and dark mode
- [ ] Footnote references link to definitions and back-links return; numbering matches GitHub
- [ ] Copy, find and outline keep working across alerts and footnotes
- [ ] Renderer regression tests and GUI evidence; README and vendored licenses/manifest updated if a plugin is vendored

## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh).

- Step 0: record GitHub golden output with `gh api /markdown -f mode=gfm` for edge cases (lowercase marker, marker+text on one line, empty alert, alert in list/nested quote, repeated ref, label case, unused definition); tests follow the fixtures.
- Footnotes: vendor `markdown-it-footnote` 4.0.0 (MIT, archive sha256 319e1c78…e272) via vendor-renderer.py; disable `footnote_inline`. Override renderers to GitHub/cmark-gfm markup: `sup.footnote-ref > a#fnref-<label>[-N]`, `section.footnotes[data-footnotes]` with `h2#footnote-label.sr-only`, `li#fn-<label>`, `a.footnote-backref` `↩︎` (+`<sup>N</sup>`). Known deviations: case-sensitive labels, last duplicate definition wins.
- `reader_metadata` must run after `footnote_tail`; reserve footnote ids in the slug set. `scrollToHeading` tries raw, decoded and `user-content-`-stripped ids.
- Alerts: in-house core rule after `block`: top-level blockquote whose first paragraph's first line is exactly `[!NOTE|TIP|IMPORTANT|WARNING|CAUTION]` (case-insensitive) → `div.markdown-alert.markdown-alert-<type>` with `p.markdown-alert-title` + inline octicon SVG (aria-hidden). Octicon paths from `@primer/octicons` 19.42.0 (MIT), source SVGs + license vendored for provenance.
- Copy: drop `.octicon`, `.footnote-backref`, `.sr-only`; refs copy as `[n]`, footnote items `[n] `; portable alert/footnote styles in rich HTML. Find skips `.sr-only`.
- CSS: GitHub alert colours light/dark as variables; footnotes section small/muted with top border.
- Tests: renderer cases for all types/negatives/nesting/math, numbering, ids, clicks, copy, find, icon provenance; GUI checks for colours in light/dark, click ref ↔ back-link scroll, native copy, find, outline.

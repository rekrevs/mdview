# T-0026: Fix quadratic render time for many identical headings

**Status**: DONE | **Size**: S

## What

The T-0021 security review found that `'\n='.repeat(n)` rendered in quadratic time (0.5 s at 8000, 1.9 s at 16000 before T-0023; 1.5 s / 5.6 s on the branch). Each `=` pair is a setext heading with the empty slug `section`, and the duplicate-id loop in `reader_metadata` counted up from 1 for every heading. A second, jsdom-visible cost was `root.replaceChildren(...template.content.childNodes)`.

## Log

- Bisected by disabling core rules: only `reader_metadata` mattered.
- Remember the last suffix per slug (`suffixes` map); ids unchanged (`a`, `a-1`, `a-1-1`, `a-2`).
- Insert the template fragment directly with `root.replaceChildren(template.content)`.

## Verification

- Red: new renderer test (16000 lines under 1.5 s) failed at 4.0 s; green after both changes. markup alone 1786 ms → 23 ms.
- `make check`: Swift 12/12, renderer 50/50. `make gui-test`: 67/67 (2000-paragraph render 8 ms).

## Outcome

Linear heading id assignment and DOM insertion.

## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh).

- View-based `QLPreviewingController` (NSViewController + WKWebView, `QLIsDataBasedPreview=false`); data-based HTML previews don't run JS. Thumbnails out of scope (follow-up).
- Appex `Contents/PlugIns/mdviewQuickLook.appex` with its own copy of the resource bundle; links inert except anchors; remote images allowed (network.client); local relative images via read-only temporary exception; 4 MiB truncation with note; 10 s render timeout; dark mode via CSS.
- Package.swift: new `ReaderCore` library target (LocalImageHandler, new `RendererPage` shared config/index lookup/render options), `mdviewQuickLook` executable target linked with `-e _NSExtensionMain` (fallback: dlsym in main.swift; plan C: swiftc in bundle.sh).
- Appex Info.plist generated in bundle.sh (`com.mdview.app.quicklook`, XPC!, NSExtension quicklook.preview, principal `MDViewPreviewController`, `QLSupportedContentTypes` net.daringfireball.markdown + whatever mdls reports). Entitlements file `Packaging/QuickLook.entitlements` (app-sandbox, network.client, read-only exception). Sign inside-out without `--deep`.
- validate-bundle checks both resource copies identical, plist keys, sandbox entitlement, principal class symbol. install.sh: lsregister, pluginkit -a/-r for backups, qlmanage -r.
- check-reader.py compiles ReaderCore first.
- Verification: `scripts/check-quicklook.sh` + `make quicklook-test` (pluginkit registration, `qlmanage -p` with os.Logger stats line: katex count, highlighted code, image loaded, inert HTML, bundle path), relocated bundle, manual Finder Space checks.
- Fallback B: data-based preview with JavaScriptCore pre-render (loses Mermaid).

## Implementation Notes

2026-11-03 (implementation agent, Opus 5.5).

- **Targets** (`Package.swift`): new library `ReaderCore` (`Sources/ReaderCore`): `LocalImageHandler` (moved with `git mv`, made public), `RendererPage` (resource-bundle lookup `indexURL(searching:)` / `index(in:)` for both SwiftPM bundle layouts, `makeConfiguration()`, `messageHandlerName`, `imageScheme`, `renderScript`, `renderOptions(for:diagrams:)`), `PreviewText` (4 MiB UTF-8-boundary truncation). App target `mdview` keeps `path: "Sources"` and the `Resources` copy, excludes `ReaderCore` and `QuickLook`, depends on `ReaderCore`. New executable target `mdviewQuickLook` (`Sources/QuickLook`) links QuickLookUI and WebKit. Test target also depends on `ReaderCore`.
- **Entry point (deviation)**: instead of `-Xlinker -e _NSExtensionMain` (unsafeFlags), `main.swift` declares `NSExtensionMain` with `@_silgen_name` and calls it. No unsafe flags; SwiftPM's own `_main` stays. `nm` shows `U _NSExtensionMain` and `_OBJC_CLASS_$_MDViewPreviewController`.
- **Preview controller** (`Sources/QuickLook/PreviewController.swift`, `@objc(MDViewPreviewController)`): view-based `QLPreviewingController`, nib-less `loadView`, one `WKWebView` with `RendererPage.makeConfiguration()`; reads at most 4 MiB + 1 byte, non-UTF-8 → error, truncation → note element prepended to `body` after render ("Preview truncated to the first 4 MiB; open in mdview to read the whole document."). Completion handler is called on the renderer's `rendered` message; 10 s timeout, provisional-navigation failure, WebContent termination or renderer `error` → error. Navigation policy allows only the bootstrap `index.html` (link activations cancelled); `link`/`headings` messages ignored (anchors are scrolled by renderer.js); `copy` → NSPasteboard. After the preview is ready it logs one `MDVIEW-QL-STATS` line (os.Logger, subsystem = extension bundle id, notice level, public fields) after diagrams, images and fonts settle (≤ 8 s): counts of `.katex`, `.math-error`, highlighted code blocks, loaded images, `.image-error`, alerts, footnote items, front matter, tables, task checkboxes, rendered/error Mermaid figures, active elements (`script, iframe, object, embed, form, link, meta, base` and `style` outside Mermaid's generated SVG), literal `<script>` text, dark mode, truncation note.
- **Mermaid decision**: diagrams stay on (no `diagrams: false`). In Quick Look the fixture's diagram rendered (`diagrams=1`) and the stats line, which waits for diagrams, arrived 0.12 s after ready; total time to ready 0.18 s debug / 0.27 s release.
- **Packaging** (`bundle.sh`): appex at `Contents/PlugIns/mdviewQuickLook.appex` with its executable, a `ditto` copy of `mdview_mdview.bundle`, and a generated Info.plist: `CFBundleIdentifier` = app id + `.quicklook` (`com.mdview.app.quicklook`), `XPC!`, versions read back from the app plist, `LSMinimumSystemVersion 13.0`, NSExtension `com.apple.quicklook.preview`, principal `MDViewPreviewController`, `QLSupportedContentTypes [net.daringfireball.markdown]` (what `mdls -name kMDItemContentType README.md` reports here; covers .md and .markdown), `QLSupportsSearchableItems false`, `QLIsDataBasedPreview false`. Signing is now inside-out without `--deep`: appex with `Packaging/QuickLook.entitlements`, then the app (no hardened runtime, matching the previous app signature).
- **Entitlements**: app-sandbox, network.client, and **narrowed** read-only temporary exceptions: `home-relative-path.read-only ["/"]` (home folder) plus `absolute-path.read-only ["/Volumes/"]`, instead of `absolute-path ["/"]`. The fixture's relative image `../../AppIcon.iconset/icon_32x32.png` loads under this (`images=1`). Images outside home and /Volumes show alt text (documented).
- **validate-bundle.sh**: retains all checks; adds appex presence, `diff -rq` of both resource bundles, no links, plutil lint and expected keys/values (id, XPC!, executable, versions equal to app, extension point, principal class, QLIsDataBasedPreview, content type), principal class symbol via `nm`, appex entitlements contain app-sandbox and network.client, `codesign --verify --strict` of appex, then the existing deep verify of the app.
- **install.sh** (not run): after install `lsregister -f` the installed app, `pluginkit -r` appexes in `mdview.app.backup-*`, `pluginkit -a` the installed appex, `qlmanage -r` / `-r cache`, enable hint; failures only warn.
- **check-reader.py**: compiles `Sources/ReaderCore/*.swift` into a static library + module first, then links it with `-I/-L/-lReaderCore`.
- **check-quicklook.sh / `make quicklook-test`**: validate-bundle; removes other *test* registrations of the id (checkout or temp folders; fails on any other copy instead of touching it); `lsregister -f` the checked app; `pluginkit -a` with confirm/retry; `qlmanage -r`; per case starts `log stream --predicate 'subsystem == "<id>"'`, runs `qlmanage -p`, waits ≤ 30 s for the expected line, captures only the qlmanage window (`screencapture -l <CGWindowID>`) to `.build/quicklook-checks/`. Cases: `Tests/QuickLook/fixture.md` (asserts bundle path and all counts above, renderSeconds < 10), a generated 5 MiB UTF-8 file (`truncated=1`, no math errors), a Latin-1 file (logged "not UTF-8" error). Temporary-folder copies are unregistered from PlugInKit and Launch Services on exit.
- Swift tests: `RendererPageTests` (flat and Contents/Resources bundle layouts, search order/missing, render options incl. `diagrams: false`) and `PreviewTextTests` (limit, boundary truncation, invalid UTF-8).
- Docs: README Quick Look section (enable, pluginkit/qlmanage commands, limitations), removed "Finder Quick Look … not implemented", Verification lists `make quicklook-test`; CLAUDE.md file map, verification command, appex/sandbox/signing/pkd notes.

## Obstacles

- **pkd drops a re-added registration after a rebuild**: `bundle.sh` replaces `mdview.app`; `pluginkit -a` right after `make bundle` was later lost (`pluginkit -m -i` → "(no matches)", Quick Look fell back to plain text). Re-adding a few seconds later is stable (checked at 0/5/10/20/40 s). The check script registers, waits 2 s and confirms, up to 3 attempts.
- **Relocated copy rejected by pkd**: `pluginkit -a` on a copy in `$TMPDIR` returned 0 but registered nothing. pkd log: `rejecting; Ignoring mis-configured plugin at [.../T/mdview-relocated/mdview.app/Contents/PlugIns/mdviewQuickLook.appex]: plug-ins outside containing apps must be protected by SIP.` with `info [PlugInKit] => [(null)]`: the containing app was unknown to Launch Services. Fix: `lsregister -f <app>` before `pluginkit -a` (the repo `mdview.app` already had a Launch Services record before this task, so it worked without). install.sh already runs `lsregister -f`.
- **One registered copy per id/version**: with the repo copy registered, adding the relocated copy kept listing only the repo path. The check script removes other test copies first.
- **`make gui-test` fails on this desktop, also at HEAD**: 45/58 with this change; the same 13 interaction checks (first: "active native test window", then native drag/copy and mouse clicks) fail on a clean `git worktree` of HEAD 185d7dc (44/58). Cause: the test window cannot become active. A system privacy prompt (UserNotificationCenter: "iTerm is requesting to bypass the system private window picker and directly access your screen and audio") stays on screen. It appeared when I took a full-screen `screencapture` early in the session; I did not answer it. Afterwards I captured only the Quick Look window. The temporary baseline worktree was removed.
- First full-screen screenshot also captured unrelated windows; it was deleted from `.build/quicklook-checks/`.

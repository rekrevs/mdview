## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh).

- Decision: in-house token-level canonicalizer (`Sources/Resources/Web/html-policy.js`, `installHTMLPolicy(md)`), not DOMPurify. Author HTML is re-emitted as escaped text plus tags built from fixed allowlisted names/attributes with validated, escaped values, so author bytes never reach WebKit as markup (no mXSS/parser differential). DOMPurify rejected: strips instead of showing text, needs whole-output DOM pass that would also hit KaTeX/hljs/Mermaid, jsdom≠WebKit.
- Disallowed tags/doctype/PI/CDATA stay visible text; raw-text elements (script, style, textarea, iframe, svg, math, template, …) shown verbatim to their close tag; disallowed attributes dropped; unsafe `a` href → text, unsafe img src → existing fallback; comments hidden (documented exception).
- Allowlist after html-pipeline: headings, p, div, blockquote, pre, lists, dl, tables, details/summary, figure, picture/source, hr, br, wbr, img, a, inline formatting (b,i,strong,em,del,ins,s,strike,sub,sup,kbd,code,tt,samp,var,q,cite,dfn,abbr,mark,small,span,time,ruby,rt,rp,bdo). Attributes: title, lang, dir, aria-label/hidden, id/name → `user-content-` prefix; a href; img src/alt/width/height/align/loading; source srcset/media/type; align/valign/width/colspan/rowspan/scope/border/start/type/value/open/datetime with strict value patterns.
- URLs: decode refs, strip tab/CR/LF/controls, then: a → fragment, relative, http(s), mailto (via md.validateLink/normalizeLink); img/srcset → relative, http(s), raster data images. No file:, mdview-image:, //host, blob:, svg data.
- Pipeline: `html:true`; core rule `author_html` pushed last converts html_block/html_inline → `author_html`; inline formatting closed per token, containers balanced across blocks via env stack; html_* renderers always escape (fail closed). Task checkbox becomes its own token type. `render()` parses into `<template>` and resolves images before insertion. scroll/find open enclosing `<details>`; copy handles picture/source/closed details.
- Defence in depth already present: CSP script-src 'self', default-src 'none', navigation policy.
- Tests: allowed constructs (exact canonical strings), disallowed visible, attribute stripping, URL corpus, Markdown parity, balancing, mXSS corpus with shared `assertInert`, survival of math/hljs/checkbox/front matter, copy/find/anchors, DOM clobbering; Swift LinkDestination hostile hrefs; GUI: summary click, kbd/align styles, picture appearance, link routing, adversarial corpus, CSP proof.

## Implementation Notes

- New `Sources/Resources/Web/html-policy.js` exposes `installHTMLPolicy(md)`. It turns on `html: true`, pushes core rule `author_html` last (after `footnote_tail`/`reader_metadata`), and overrides the `html_block`/`html_inline` renderers so they always escape (fail closed). The core rule scans each `html_block` and each `html_inline` child with the CommonMark tag grammar (open/close tag, comment, PI, CDATA, declaration) and re-emits them as `author_html` tokens: escaped text (character references decoded, then escaped), plus allowlisted tags rebuilt from fixed names with validated, decoded, double-quoted and escaped attribute values. The first duplicate attribute wins and all others are dropped.
- Allowlists, attribute rules and URL rules follow the agreed plan. `id`/`a[name]` → `user-content-` prefix. `a[href]` accepts fragments, relative URLs, http(s) and mailto; it goes through WHATWG preprocessing (decode, strip tab/CR/LF anywhere and C0/space at the ends), rejects `//`, `\\`, `/\` and any backslash, rejects any other scheme or a colon in the first path segment, then applies `md.normalizeLink` and `md.validateLink`, so the output equals the href the equivalent Markdown link produces. `img[src]` and each `srcset` candidate accept relative URLs, http(s) and `data:image/(png|gif|jpeg|webp);` only, and one bad candidate drops the whole srcset. An unsafe `a` href leaves its content as plain text (a phantom stack entry consumes the matching `</a>`). An unsafe/missing `img` src produces the existing "Image unavailable: alt" fallback.
- Raw-text elements (script, style, textarea, title, xmp, iframe, noembed, noframes, noscript, plaintext, template, svg, math, select, object) in an HTML block are shown verbatim through their close tag. In an inline run, every HTML token up to the matching close tag is escaped, and Markdown text between them renders normally as text. Other disallowed tags, PIs, CDATA and doctype stay visible as text. Comments are omitted, and a comment-only block emits nothing.
- Balancing: each author element records the trusted nesting depth (block token depth, or inline child depth) at which it opened. A close tag only matches entries at the current depth, and unmatched close tags are dropped. Before a trusted close token, author entries at that depth or deeper are closed. Inline-run tags close at the end of their inline token, and inline tags opened in an HTML block close at the end of that block. Containers can span blocks, are closed before `footnote_block_open`, and leftovers are closed at the end of the document. Non-void self-closing tags (`<a name="x"/>`) emit open+close.
- renderer.js: `html: true` + `installHTMLPolicy(md)`. The task checkbox is now a `task_checkbox` token with its own renderer rule; no other trusted markup used `html_*` tokens (audited). `render()` parses into an inert `<template>`, resolves images through `prepareImage(img, baseURL)` (referrer policy, error fallback, missing src → fallback) and `picture > source[srcset]` candidates through `imageURL()` (orphan `source` loses srcset), then `root.replaceChildren(...)`. `scrollToHeading` also tries `user-content-<id>` and `<a name>` via `getElementsByName`, and opens closed ancestor `<details>`. `find()` opens the details that contains the active match, and the indexText block list gained DETAILS/SUMMARY/DL/DT/DD/FIGURE/FIGCAPTION/CAPTION. Copy drops `<source>`, keeps only `<summary>` of closed details, separates the new block tags, adds portable KBD/MARK styles and strips `name` (ids already stripped). `window.mdview.markup(text)` exposes the pure Markdown→HTML string for exact canonical tests.
- reader.css: kbd, details/summary, dl, mark, figure/figcaption, `img[align=left|right]` floats. `img:not([height]) { height:auto }` lets height attributes work. `align` on p/div/table uses WebKit's native presentational hints; a generic `[align]` text-align rule was rejected because it would centre text inside `<table align=center>`.
- index.html loads `html-policy.js` before `renderer.js`, with the CSP unchanged. `scripts/validate-bundle.sh` requires `html-policy.js`, and the renderer test harness loads it.
- Docs: README (HTML subset section, blank-line rule, visible disallowed tags, hidden comments, `user-content-` ids, math literal in HTML blocks, raw headings not in outline; "Raw HTML is shown as text" replaced). CLAUDE.md architecture and constraint wording as agreed. T-0024 criterion → "same HTML policy as the reader". No vendored code, so THIRD_PARTY/manifest unchanged.

## Obstacles

- Initial test expectations assumed one-line `<picture>…</picture>` and `<br/> …` lines were HTML blocks. Under CommonMark they are paragraphs with inline HTML (picture/br are not type-6 names, and type 7 needs the tag alone on its line). I corrected the expectations. `ok.png,,` is a valid srcset per the HTML spec, so I replaced that case with `, ,`.
- Commas in resolved srcset URLs were percent-encoded for every candidate, which corrupted `data:` URLs. Now only `mdview-image:` URLs are encoded.
- GUI: WebKit keeps a layout box for content inside a closed `<details>` (`getBoundingClientRect` 1112×25.6 while closed), so I replaced the first "hidden" probe with `innerText` + `checkVisibility()`.
- Pathological inputs (20k unterminated `<!--`/`<?`/`<!A` openers) took 0.3–0.8 s because the lazy regexes are quadratic. A per-construct "terminator occurs later" guard brought each case to ≤4 ms. `x <!--×20000` inline still takes about 0.8 s, but that is markdown-it's own html_inline cost (748 ms with plain markdown-it, policy not involved).

## Outcome

Independent security review (code-reviewer agent, read-only, probes in jsdom/parse5): no script execution, out-of-policy URL, encoding/quoting bypass or super-linear input found. Two low-severity integrity findings fixed by the coordinating session:
1. Inline block tags (`<li>`, `<td>`, `<h2>`, `<hr>`, containers) in a paragraph/heading/cell made the HTML parser close trusted structure (forged footnote numbering). Inline runs now emit only phrasing tags (inline formatting, br, wbr, img, picture, source); other open tags stay visible text, their close tags are dropped. Footnote copy numbering now counts `li.footnote-item` only.
2. An author `id` could equal a heading slug (`# user-content-intro`); `scrollToHeading` now prefers a heading element.
Regression tests added (renderer 49/49). Re-verified: `make check` Swift 12/12 + renderer 49/49, `make gui-test` 67/67, `make validate-bundle` OK.
Noted, not fixed here: privacy — HTML allows invisible remote images and prefers-color-scheme `<source>` (same remote-image policy as Markdown).


GitHub-style HTML subset renders through an in-house canonicalizer: no author bytes reach WebKit as markup, disallowed markup stays visible, links/images share the Markdown classification and resolution, and trusted renderer output cannot be forged. Residual risks: (1) the "no canary fetch" GUI check has no positive control, because WebKit may not record resource-timing entries for failed loads. The renderer tests prove those elements are never emitted. (2) Allowed elements can still reshape trusted structure through ordinary HTML parser rules (e.g. an author `<li>` or `<td>` implicitly closing a trusted one). This is cosmetic only, since classes, data attributes and handlers cannot be authored. (3) Remote http(s) images in HTML follow the existing Markdown image policy (fetched, no referrer). (4) jsdom is not WebKit. The GUI corpus covers the real engine for a representative subset.

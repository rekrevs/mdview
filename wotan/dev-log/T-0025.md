# T-0025: Support emoji shortcodes and light/dark image variants

**Status**: DONE | **Size**: M
**Phase**: -

## Context

GitHub converts `:rocket:` shortcodes and honours `#gh-dark-mode-only` / `#gh-light-mode-only` image fragments.

## Acceptance Criteria

- [x] Known GitHub emoji shortcodes render as Unicode emoji; unknown shortcodes and code spans are untouched
- [x] Images tagged #gh-dark-mode-only / #gh-light-mode-only show only in the matching appearance
- [x] Renderer tests and GUI evidence; README and licenses/manifest updated if data is vendored

## Approach

Planned 2026-11-03 (Plan agent, Opus 5.5 xhigh).

- Emoji: vendor `markdown-it-emoji` 3.1.0 `dist/markdown-it-emoji.min.js` (MIT, 1903 names ⊂ gemoji 8.1.0; missing 10 CJK `:uXXXX:` names and Unicode 15.1+). `md.use(markdownitEmoji, {shortcuts:{}})` — emoticons disabled (not GitHub; `:$` would clash with math). Only text tokens rewritten, so code, math, link destinations, autolinks untouched. Custom image emoji (`:octocat:`) stay text.
- Heading slug keeps the shortcode name (`#rocket-launch`), title shows emoji: heading metadata runs after `emoji` and uses `markup` for slugs.
- Image variants: tag images whose raw src ends with `#gh-dark-mode-only`/`#gh-light-mode-only` with matching classes (also on the error fallback); CSS hides by `prefers-color-scheme` (live). Copy and find skip the inactive variant (matchMedia, light default). Shared contract with T-0021 (`<picture>`, HTML images through same image preparation).
- Tests: renderer cases for emoji positives/negatives, slug/title, copy/find, variant classes, local URL, copy per appearance (stubbed matchMedia); GUI: emoji render/copy/find, explicit aqua/darkAqua appearance switch showing the right variant and copy.
- Docs: README, THIRD_PARTY, manifest, validate-bundle, index.html, CLAUDE.md library list.

## Log

- 2026-11-03: Inspected the markdown-it-emoji 3.1.0 tarball: `dist/markdown-it-emoji.min.js` is a UMD build whose global `markdownitEmoji` is the full plugin itself (no `.full`); it inserts core rule `emoji` after `linkify`, rewrites only top-level inline `text` tokens outside autolinks, and emits `emoji` tokens (`markup` = name, `content` = character). Archive sha256 `9ce648b8…a266`.
- Vendored through `PACKAGES` in `scripts/vendor-renderer.py`. Direct mode failed after five retries (IncompleteRead on one archive), so all pinned archives (7 main + 108 Mermaid bundled) were fetched with `curl --retry 5` and the script ran in local-archive mode. Only `manifest.json` changed among existing vendored files (`git diff --stat Sources/Resources/Web/vendor`); new: `markdown-it-emoji.min.js`, `licenses/markdown-it-emoji.txt`.
- Tests first: 8 renderer tests added; harness loads the plugin. Red 64/72.
- Emoji (renderer.js): `md.use(markdownitEmoji, { shortcuts: {} })`; new core rule `emoji_literal_code` after `emoji` turns emoji back into text between inline author `<code>`/`<pre>`/`<tt>` tags (GitHub skips those parents); `reader_metadata` now runs after it (still after `footnote_tail`), uses emoji `markup` for the slug and `content` for the title. Task checkbox detection unchanged (first text token is still `[x] `).
- Emoji in HTML blocks (html-policy.js): `installHTMLPolicy(md, { blockText })`; block text pieces outside an open `pre`/`code`/`tt` are converted with a separate `markdownit('zero')` + emoji instance (`parseInline`, so no other Markdown rule applies), then escaped as before. Inline-HTML text in paragraphs is ordinary Markdown text and converts naturally.
- Variants: `prepareImage` tags images whose raw `src` ends in `#gh-(dark|light)-mode-only` with class `gh-…-mode-only` before resolution; `imageFallback` copies the class. `imageURL` drops the fragment for local files (`url.pathname`); remote URLs keep it. reader.css hide-only rules. Copy removes the inactive variant before images become alt text; `indexText` skips it. Appearance read with `matchMedia('(prefers-color-scheme: dark)')`, light default (Mermaid's `colorScheme` is only initialised lazily for diagram documents, so not reused).
- Deviations from the plan: (1) `a:b:c` converts `:b:` (🅱️) — GitHub's html-pipeline EmojiFilter pattern is `:(names):` without word boundaries, so the test asserts `a:zz:c` literal and `a:tada:b` → `a🎉b` instead. (2) Emoji in HTML text: converted (as GitHub converts every text node except under pre/code/tt), including HTML blocks via the policy hook. (3) Image alt text keeps shortcodes (GitHub only converts text nodes). (4) Broken-variant test uses `ftp:` (markdown-it rejects `javascript:` image links at parse time, leaving text).
- GUI section in ReaderChecks.swift before the adversarial corpus: explicit `.aqua` → `.darkAqua` → `.aqua`, same DOM nodes checked across the switch.
